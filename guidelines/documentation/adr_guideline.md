# アーキテクチャ決定記録 (ADR) ガイドライン

## 位置付け
- **目的**: 個々の重要な技術・設計判断とその背景、選択肢、影響範囲を時系列で記録し、意思決定を透明化する。
- **対象**: システム構造や運用に中長期的影響を与える決定（例: 新フレームワーク導入、データストア切替、運用体制の大幅変更）。
- **更新タイミング**: 決定が下された直後。既存ADRの決定を変える場合は新しいADRを起票し、旧ADRのステータスを「Superseded by ADR-NNNN」に更新する（採択済みADRの本文は書き換えない）。

## ドキュメントとの役割分担
- **Architecture.md**: 現時点で採用しているアーキテクチャの全体像と理由を俯瞰的に説明する「設計憲章」。ADRで確定した決定のうち現在有効なものを統合的に反映する。
- **内部仕様書**: 各機能・運用手順の具体的な仕様書。ADRの決定結果を前提として詳細を記すが、意思決定プロセス自体は含めない。
- **ADR**: 個別の意思決定のログ。`背景と課題 → 決定要因 → 選択肢 → 決定 → 結果` の形式で、議論の背景や他案との比較も明示する。

## 記述テンプレート

[`templates/adr/adr.md`](../../templates/adr/adr.md) をコピーして使用する。[MADR](https://adr.github.io/madr/) をベースに、以下の構成としている。

| 章 | 書くこと |
|---|---|
| 1. 背景と課題 | なぜ今決める必要があるか。最後は「〜をどうするか？」という問いで締める |
| 2. 決定要因 | 選択肢を評価する基準（要件・制約・品質特性） |
| 3. 検討した選択肢 | 現状維持も含めて列挙 |
| 4. 決定 | 採用した選択肢と理由、良い影響・悪い影響、実施確認の方法 |
| 5. 選択肢ごとの比較 | 比較表と、各選択肢の良い点・悪い点・却下理由 |
| 6. 補足情報 | PoC結果、参考資料、議論の記録 |

### ステータス

| ステータス | 意味 |
|---|---|
| Proposed | 提案中。レビュー・合意形成中 |
| Accepted | 採択。現在有効な決定 |
| Rejected | 検討の結果、採用しなかった（記録として残す） |
| Deprecated | 廃止。後継の決定はない |
| Superseded by ADR-NNNN | 別のADRに置き換えられた |


## 運用ヒント
- ADRは `docs/adr/ADR-NNNN-short-title.md` のように4桁の連番で管理し、`docs/adr/README.md` で一覧（番号・タイトル・ステータス）を索引化する。
- Architecture.md は最新の全体像を保つため、採択済みADRの要約を定期的に取り込み、現状と乖離したADRは Superseded として整理する。
- 大きな変更を計画する際は、先にドラフトADRを作成して検討材料を可視化し、合意形成後にステータスを更新すると運用が楽になる。
