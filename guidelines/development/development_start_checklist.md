# 開発開始時に確認することテンプレート

## 0. この資料の目的

新規開発・改修開発を開始する前に、実装へ入る前提を整理するための確認項目テンプレート。  
要件定義・基本設計・実装方針・運用方針の抜け漏れを減らすことを目的とする。

各項目の詳しい確認観点は以下を参照。

| 項目 | 関連文書 |
| --- | --- |
| 1〜3章（前提・スコープ・要件） | [要件確認チェックリスト](../requirements/requirements_checklist.md) |
| 4〜5章（技術選定・アーキテクチャ） | [ADRガイドライン](../documentation/adr_guideline.md) / [アーキテクチャ文書](../../templates/04_architecture/architecture.md) |
| 9章（セキュリティ） | [公開前チェックリスト](../security/public_release_checklist.md) |

## 1. プロジェクト前提

- [ ] プロジェクト名を確認する
- [ ] 開発目的を確認する
- [ ] 解決したい課題を確認する
- [ ] 対象ユーザーを確認する
- [ ] 利用シーンを確認する
- [ ] MVPなのか正式版なのかを確認する
- [ ] 新規開発か既存改修かを確認する
- [ ] 社内向けか外部顧客向けかを確認する
- [ ] 納期・マイルストーンを確認する
- [ ] 開発体制・担当範囲を確認する
- [ ] 意思決定者・レビュー担当者を確認する
- [ ] 未決事項の管理方法を決める

---

## 2. スコープ確認

### 2.1 対応範囲

- [ ] 今回作る機能を明確にする
- [ ] 今回作らない機能を明確にする
- [ ] MVPで割り切る範囲を明確にする
- [ ] 正式版で対応する範囲を明確にする
- [ ] 将来拡張を見越す部分を明確にする

### 2.2 受け入れ条件

- [ ] 何ができれば完了なのかを確認する
- [ ] 機能ごとの受け入れ条件を定義する
- [ ] 受け入れ確認の方法を定義する
- [ ] テスト環境で確認するのか本番相当環境で確認するのかを決める
- [ ] 顧客・依頼者が確認する項目を決める

---

## 3. 要件確認

### 3.1 業務要件

- [ ] 業務フローを確認する
- [ ] 現在の運用を確認する
- [ ] 新システム導入後の運用を確認する
- [ ] 手作業で残す作業を確認する
- [ ] システム化する作業を確認する
- [ ] 例外的な業務パターンを確認する

### 3.2 機能要件

- [ ] 機能一覧を作成する
- [ ] 画面が必要な機能を確認する
- [ ] APIが必要な機能を確認する
- [ ] バッチ処理が必要な機能を確認する
- [ ] 通知・メール送信が必要な機能を確認する
- [ ] ファイルアップロード・ダウンロードの有無を確認する
- [ ] 外部サービス連携の有無を確認する
- [ ] 管理画面の有無を確認する

### 3.3 非機能要件

- [ ] 性能要件を確認する
- [ ] 可用性要件を確認する
- [ ] セキュリティ要件を確認する
- [ ] 拡張性要件を確認する
- [ ] 保守性要件を確認する
- [ ] 監視要件を確認する
- [ ] バックアップ要件を確認する
- [ ] 障害対応要件を確認する

---

## 4. 技術選定

- [ ] 使用言語を決める
- [ ] フレームワークを決める
- [ ] DBを決める
- [ ] キャッシュ・キューの有無を決める
- [ ] フロントエンド構成を決める
- [ ] バックエンド構成を決める
- [ ] インフラ構成を決める
- [ ] 外部サービスを決める
- [ ] ライブラリ・SDKを決める
- [ ] 採用技術のバージョンを確認する
- [ ] 技術的に検証が必要な箇所を洗い出す
- [ ] 代替案を用意する

---

## 5. アーキテクチャ確認

- [ ] システム全体構成図を作る
- [ ] フロントエンド・バックエンド・DB・外部サービスの関係を整理する
- [ ] 同期処理・非同期処理を整理する
- [ ] キュー・ワーカーの有無を確認する
- [ ] バッチ処理の有無を確認する
- [ ] リトライが必要な処理を確認する
- [ ] 冪等性が必要な処理を確認する
- [ ] トランザクション境界を確認する
- [ ] データ整合性の担保方法を確認する
- [ ] 障害時に処理が止まる箇所を確認する

---

## 6. データ設計

- [ ] 主要エンティティを洗い出す

- [ ] ユニーク制約を確認する
- [ ] インデックスを確認する
- [ ] 論理削除・物理削除の方針を決める
- [ ] 監査ログの必要性を確認する
- [ ] 個人情報・機密情報の保存有無を確認する
- [ ] データ保持期間を確認する
- [ ] データ移行の有無を確認する

## 7. API設計

- [ ] API一覧を作成する

- [ ] ページネーション方針を決める
- [ ] ソート・検索・フィルタ条件を決める

## 9. セキュリティ
