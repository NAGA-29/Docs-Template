# Webサービス公開前ガイドライン（チェックリスト）

> 参考: catnoseさん「Webサービス公開前のチェックリスト」  
> https://zenn.dev/catnose99/articles/547cbf57e5ad28

このチェックリストは、Webサービスを本番公開する前に最低限確認すべき項目を、実務で使いやすい形に整理したものです。  
サービス要件によって不要な項目もあるため、該当しないものは `N/A` として扱ってください。

---

## 0. 使い方

- [ ] 各項目について `OK / NG / N/A` を判断する
- [ ] `NG` の項目は、公開前に対応するか、リスクを明文化して承認を取る
- [ ] 決済・個人情報・メール送信・外部公開URLに関わる項目は優先度を上げる
- [ ] 公開直前だけでなく、機能追加・仕様変更時にも再チェックする

---

## 1. セキュリティ

### 1.1 認証Cookie

- [ ] 認証Cookieに `HttpOnly` が設定されている
- [ ] 認証Cookieに `Secure` が設定されている
- [ ] 認証Cookieの `SameSite` が `Lax` または `Strict` になっている
- [ ] `SameSite=Lax` の場合、GETリクエストでデータ更新・削除が行われない
- [ ] Cookieの `Domain` 属性が必要以上に広く設定されていない
- [ ] サブドメインにCookieを共有する場合、そのリスクを把握している
- [ ] 可能であれば認証Cookie名に `__Host-` プレフィックスを使っている

### 1.2 入力値バリデーション

- [ ] 入力値の検証をクライアント側だけでなくサーバー側でも行っている
- [ ] URL入力欄では `javascript:` など危険なプロトコルを拒否している
- [ ] URLや文字列の正規表現バリデーションにバイパス余地がない
- [ ] ユーザー入力をHTMLとして出力する箇所を把握している
- [ ] `innerHTML` や `dangerouslySetInnerHTML` を使う場合、サニタイズしている
- [ ] SQLインジェクションが起きる可能性のあるSQL組み立てをしていない
- [ ] URLパスに使うユーザー名・ハンドル名の制約を定義している
- [ ] `admin`, `contact`, `settings`, `api` など予約語をユーザー名に使えない
- [ ] 数字だけ、アンダースコア始まり、フレームワークやクラウドの予約パスと衝突する文字列を拒否している

### 1.3 レスポンスヘッダ

- [ ] `Strict-Transport-Security` を設定している
- [ ] クリックジャッキング対策として CSP の `frame-ancestors` を設定している
- [ ] `X-Content-Type-Options: nosniff` を設定している
- [ ] 必要に応じて Content Security Policy（CSP）を設定している

### 1.4 認可・権限

- [ ] 更新・削除処理で未認証ユーザーが操作できない
- [ ] 更新・削除処理で権限のないユーザーが他人のデータを操作できない
- [ ] ID指定APIで他ユーザーのリソースを参照・更新できない
- [ ] 管理者用API・管理画面に一般ユーザーがアクセスできない
- [ ] メールアドレス変更・退会・決済情報変更など重要操作では再認証を要求している

### 1.5 キャッシュ・ストレージ

- [ ] ユーザーごとに内容が変わるレスポンスがCDNや共有キャッシュに保存されていない
- [ ] 認証が必要なAPIレスポンスに不適切なキャッシュヘッダが付いていない
- [ ] オブジェクトストレージの一覧表示・ディレクトリリスティングが公開されていない
- [ ] 画像URLやファイルURLから他ユーザーのファイルを推測できない

### 1.6 リダイレクト・ヘッダ・エラー

- [ ] クライアントから渡されたURLへ無検証でリダイレクトしていない
- [ ] `redirect_to` などの戻り先URLは、自サービス内または許可リスト内に限定している
- [ ] ユーザー入力をそのままレスポンスヘッダに含めていない
- [ ] サーバー内部のエラーメッセージ・スタックトレースをブラウザに表示していない

### 1.7 ファイルアップロード

- [ ] アップロード可能なファイル形式を制限している
- [ ] ファイルサイズ上限を設定している
- [ ] ファイル名をそのまま保存・公開URLに使っていない
- [ ] 拡張子だけでなく MIME type や実体の検証も行っている
- [ ] アップロードファイルを直接実行可能な場所に置いていない

### 1.8 DB・バックアップ・クラウドアカウント

- [ ] DBの自動バックアップが有効になっている
- [ ] オブジェクトストレージのバックアップまたはバージョニングが有効になっている
- [ ] 本番クラウドアカウントに二要素認証を設定している
- [ ] 本番環境の権限が最小権限になっている
- [ ] DELETE / UPDATE 文に適切な WHERE 条件がある
- [ ] 一括更新・一括削除系の処理に誤爆防止策がある

---

## 2. ログイン・アカウント

- [ ] メールアドレスの本人確認を行っている
- [ ] 外部IDプロバイダから渡されたメールアドレスの検証状態を確認している
- [ ] ログイン画面・パスワード再設定画面で登録済みメールアドレスを列挙できない
- [ ] 複数ログイン方式がある場合、同一メールアドレスで登録されたときの仕様が決まっている
- [ ] メールアドレス変更の導線がある
- [ ] 外部連携アカウントの変更・解除導線がある
- [ ] パスワードログインがある場合、パスワード変更導線が分かりやすい

---

## 3. メール送信

- [ ] ユーザー入力がメール本文や件名に入る場合、スパム的に悪用されない
- [ ] 1つの操作で不特定多数に大量メールが送られない
- [ ] 通知メールの送信条件にレート制限・重複防止がある
- [ ] SPF を設定している
- [ ] DKIM を設定している
- [ ] DMARC を設定している
- [ ] バッチやキューの再実行時に同じメールが重複送信されない
- [ ] メルマガ・キャンペーンメールはログインなしで配信停止できる
- [ ] 大量配信を行う場合、List-Unsubscribe / One-Click Unsubscribe を検討している

---

## 4. SEO

- [ ] 各ページの `title` が適切に設定されている
- [ ] 重要ページに `canonical URL` を設定している
- [ ] 404 / 500 系ページが適切なHTTPステータスを返している
- [ ] 検索結果ページに `noindex` または canonical を設定している
- [ ] サイト全体に誤って `noindex` が付いていない
- [ ] トップページや重要LPに meta description を設定している
- [ ] 動的に公開ページが増える場合、XMLサイトマップを生成している
- [ ] Search Console に登録している

---

## 5. OGP・SNS共有

- [ ] 共有される可能性のあるページに OGP を設定している
- [ ] `og:title` が適切
- [ ] `og:description` が適切
- [ ] `og:url` が正規URLになっている
- [ ] `og:image` が設定され、実際に表示確認済み
- [ ] `twitter:card` を設定している
- [ ] SNS投稿時のプレビューを確認している

---

## 6. 決済機能

- [ ] 会計処理・売上計上・返金ルールを担当者と確認している
- [ ] 決済サービス側の成功とアプリDB更新の不整合を検知できる
- [ ] 決済成功後のDB更新失敗に対するリカバリー手段がある
- [ ] 重複決済が発生しない実装になっている
- [ ] 決済済みユーザーが退会しても会計・履歴・権限に不整合が出ない
- [ ] サブスク契約中の退会・凍結時の扱いが決まっている
- [ ] サブスク解約導線が分かりやすい
- [ ] カード期限切れ・支払い失敗時のハンドリングがある
- [ ] 支払い情報更新の導線がある
- [ ] 返金・日割り・退会時の扱いが利用規約に書かれている
- [ ] 適格請求書が必要な場合、領収書・請求書が要件を満たしている

---

## 7. アクセシビリティ

- [ ] 画像に適切な `alt` 属性が設定されている
- [ ] 装飾画像には空の `alt` を設定している
- [ ] SVGアイコンだけのボタン・リンクに `aria-label` などで役割を与えている
- [ ] キーボードだけで主要操作ができる
- [ ] フォーカス位置が視覚的に分かる
- [ ] フォームエラーがスクリーンリーダーでも把握できる
- [ ] 色だけに依存した情報伝達をしていない

---

## 8. パフォーマンス

- [ ] bundle analyzer などで不要なJSが含まれていないか確認した
- [ ] 静的ファイルがCDNから配信されている
- [ ] 画像に `width` / `height` または `aspect-ratio` を指定し、レイアウトシフトを防いでいる
- [ ] 表示サイズに対して過剰に大きい画像を配信していない
- [ ] 画像の圧縮・WebP/AVIFなどの利用を検討している
- [ ] SQLのインデックスが主要クエリに対して適切に設定されている
- [ ] N+1クエリが発生していない
- [ ] 初回表示・主要操作のレスポンス時間を確認している

---

## 9. 複数環境での動作確認

- [ ] スマホ幅でUIが崩れない
- [ ] タブレット幅でUIが崩れない
- [ ] PC幅でUIが崩れない
- [ ] Chromeで確認した
- [ ] Safariで確認した
- [ ] Firefoxで確認した
- [ ] iOS Safariで確認した
- [ ] Android Chromeで確認した
- [ ] Mac / Windows / iOS / Android でフォント表示が不自然でない
- [ ] 長いユーザー名・長いタイトル・長いURLでもレイアウトが崩れない
- [ ] スクロールバー常時表示設定でもモーダルやレイアウトが崩れない

---

## 10. ブラウザ仕様・ストレージ依存

- [ ] ローカルストレージが消えても致命的な問題が起きない
- [ ] HttpOnlyでないCookieが消えても致命的な問題が起きない
- [ ] iOS Safari の ITP によるストレージ削除を考慮している
- [ ] サードパーティCookieに依存していない
- [ ] 認証・トラッキング・埋め込み機能がブラウザ制限で壊れないか確認している

---

## 11. 運用・監視

- [ ] サーバーエラーを検知できる
- [ ] 重要な例外が通知される
- [ ] ログが本番環境で確認できる
- [ ] 個人情報・トークン・パスワードがログに出力されていない
- [ ] 404ページにトップページや検索など次の導線がある
- [ ] 50xページが最低限ユーザーに不安を与えない内容になっている
- [ ] favicon を設定している
- [ ] apple-touch-icon を設定している
- [ ] 必要に応じてアクセス解析を導入している

---

## 12. 法務・規約・サービス名

- [ ] 利用規約を用意している
- [ ] プライバシーポリシーを用意している
- [ ] 特定商取引法表記が必要な場合、用意している
- [ ] クローズドチャットなど通信サービスに該当する場合、電気通信事業の届出要否を確認している
- [ ] サービス名が他言語で不適切な意味を持たないか確認している
- [ ] 商標・既存サービス名との衝突を確認している

---

## 13. 公開直前の最終確認

- [ ] 本番環境の環境変数が正しい
- [ ] 本番DBに接続している
- [ ] テスト用APIキー・テスト用決済キーが残っていない
- [ ] デバッグモードが無効になっている
- [ ] 管理画面・管理APIが外部から不用意に見えていない
- [ ] robots.txt の設定が意図通り
- [ ] noindex の解除漏れがない
- [ ] バックアップからの復旧手順を確認している
- [ ] 公開後に見るべきログ・メトリクスが決まっている
- [ ] 障害発生時の切り戻し手順がある

---

## 14. 優先度の目安

### 最優先で潰すべき項目

- 認証Cookie設定
- 認可漏れ
- SQLインジェクション
- XSSにつながるHTML出力
- オープンリダイレクト
- 個人情報のキャッシュ事故
- ファイルアップロードの検証漏れ
- 決済の重複・不整合
- バックアップ未設定
- エラー検知なし

### 後回しにしてもよいが、公開前に判断すべき項目

- SEO最適化
- OGPの細部調整
- アクセシビリティの高度な改善
- パフォーマンス最適化の細部
- Search Console / Analytics の細かい設定

ただし、公開サービスの性質によって優先度は変わります。たとえば、集客用LPならSEO・OGPは優先度が高く、業務用管理画面なら認証・認可・監査ログの優先度が高くなります。
